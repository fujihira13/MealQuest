# セキュリティレビュー

実装コードに対して、AI固有リスクとOWASP主要項目（A01/A02/A03/A05/A06/A07/A09/A10）の観点からセキュリティ脆弱性を検出するワークフロー。

> 参照:
> - `.Codex/skills/security-review/references/ai-security-checklist.md`
> - `.Codex/skills/security-review/references/owasp-checklist.md`

---

## Step 1: スコープ確認

引数またはコンテキストからレビュー対象を特定する。

**判定すること:**

1. **レビュー対象ファイル・機能**: 引数に指定がある場合はそれを使う。ない場合は直近の実装変更を対象とする
2. **AIアプリケーション判定**: 以下のいずれかに該当すればAIアプリとして扱う
   - `anthropic` / `openai` / `langchain` / `llamaindex` など LLM SDK のインポートがある
   - ユーザー入力をプロンプトに組み込む処理がある
   - 外部APIから取得したデータをプロンプトに挿入する処理がある

**不明な場合のみ** AskUserQuestion で確認（最大2項目）:
- レビュー対象ファイルが特定できない場合
- AIアプリかどうかコードだけでは判断できない場合

---

## Step 2: コード読み込みとリファレンス参照

対象ファイルを Read ツールで読み込む。

リファレンスは**必要セクションのみ**参照する（コンテキスト節約）:
- AIアプリの場合 → `references/ai-security-checklist.md` のセクション1〜5を参照
- 全ケース → `references/owasp-checklist.md` の対象機能に関連するセクションのみ参照
  - 例: DBアクセスなし → A03(SQLi)は省略可（ただしA03(コマンドインジェクション)はOSコマンド実行があれば必須）
  - 例: URLフェッチなし → A10(SSRF)は省略

---

## Step 3: チェックリスト実行

### AIアプリ固有チェック（Step 1でAIアプリと判定された場合のみ）

`references/ai-security-checklist.md` に基づいてチェック:

- **直接プロンプトインジェクション**: ユーザー入力が検証なしにプロンプトへ混入していないか
- **間接プロンプトインジェクション**: 外部データ（Web、DB、ファイル）取得→プロンプト挿入の経路
- **システムプロンプト漏洩**: レスポンスにシステムプロンプトが含まれる可能性
- **LLM過剰権限**: 関数呼び出し・ツール使用の許可スコープが最小権限原則に従っているか
- **LLM出力の安全な処理**: 出力をそのままHTMLレンダリング・evalなどに使っていないか

### OWASP 主要項目 実装チェック（全ケース）

`references/owasp-checklist.md` に基づいてチェック:

- **A01 アクセス制御の欠陥**: IDOR・水平権限昇格の実装検証
- **A02 暗号化の失敗**: 安全な乱数（Math.random禁止）、適切なハッシュ（bcrypt/argon2）
- **A03 インジェクション**: SQLiのプリペアドステートメント確認、コマンドインジェクション（shell:true禁止）
- **A05 セキュリティの設定ミス**: デフォルト認証情報・デバッグモード・不要なサービス公開
- **A06 脆弱なコンポーネント**: 既知脆弱性を持つ依存ライブラリ
- **A07 認証の失敗**: ブルートフォース対策・レート制限・パスワードポリシー
- **A09 ログ記録の不備**: センシティブ情報（パスワード・トークン・PII）のログ記録禁止
- **A10 SSRF**: 外部URL取得時のドメインバリデーション・DNS再検証
- **シークレット/APIキーのハードコード**: ソースコード内の認証情報の直書き検出
- **エラーメッセージの情報漏洩**: スタックトレース・内部情報の露出
- **タイミング攻撃耐性**: 認証処理での crypto.timingSafeEqual 使用確認

## Step 4: レポート出力

以下のフォーマットでセキュリティレビュー結果を出力する。

```
## セキュリティレビュー結果

**対象**: [ファイル名またはスコープ]
**総合判定**: ✅ PASS / ⚠️ 要修正

---

### CRITICAL（即時修正必須）
- [ファイル:行番号] **問題の説明**
  - リスク: ...
  - 修正方法: ...

### HIGH
- [ファイル:行番号] **問題の説明**
  - リスク: ...
  - 修正方法: ...

### MEDIUM
- ...

### LOW
- ...

### 確認済み（問題なし）
- A03 インジェクション: プリペアドステートメント使用確認済み
- ...（問題がなかった項目を列挙）

---

**修正推奨優先度**: CRITICAL → HIGH の順に対応してください
```

問題が0件の場合は `✅ PASS` とし、確認済み項目を全て列挙する。
